# Architecture decisions

One file per decision that is hard to reverse or would surprise a newcomer: a framework, a
boundary, a data shape, a tradeoff the code alone does not explain. Record them with the
`domain-modeling` skill.

- File: `NNNN-short-title.md`, numbered in order, never renumbered.
- Sections: **Status** (`Accepted`, `Superseded by NNNN`), **Context** (the forces, with facts),
  **Decision** (what we do), **Consequences** (what gets easier, what gets harder).
- A decision that changes gets a new ADR that supersedes the old one; the old file stays, with
  its status updated.
- Domain terms used in ADRs and code are defined once in `GLOSSARY.md` at the root.
